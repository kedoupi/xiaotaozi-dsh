## 0. 一句话

**我们是企业微信对话里的腾讯文档排版工具：AI 按这件事的去向，把内容编排成打开就能看、敢发出去的腾讯文档。**

不是模板库。不是「再提供一个创建文档的按钮」。

---

## 1. 我们是谁

`dsh-wecom-office` 已经能在对话里创建腾讯文档。缺的不是通道，是交出去的那一份配不配得上「文档」这两个字。

本能力挂在企业微信办公插件上，身份是：

| 我们是 | 我们不是 |
| :-- | :-- |
| 排版工具 | 文档类型商店 |
| 对话里的文档成品能力 | Word / PPT 企业模板工厂 |
| 用 AI 做智能编排的产品 | 让用户先选模板再填空的表单 |
| 腾讯文档上的排版 | 自研在线编辑器，或模拟点击格式按钮的 RPA |

「智能编排」对我们是本职，不是附加功能。人要先想章节、列表、表格、语气；AI 应当直接按去向完成这些判断，再交到腾讯文档里。

---

## 2. 问题

用户在对话里说「做成一份文档」。今天插件会创建成功，字也往往在。打开腾讯文档后，却像聊天记录或 AI 草稿：标题不像标题，段落是一堵墙，该是表的地方还是长句，开头还在说「好的，我来整理」。

没有人愿意不改就转发出去。

失败不在「会不会建文档」，在「建出来的不像文档」。

用户真正要的时刻，也不是打开模板中心勾选「会议纪要 / 产品文档 / 技术文档」。而是正在聊项目、聊方案、聊代码，然后说：

- 把整个项目做成介绍；
- 要给第三方机构推；
- 给开发者一份能动手的材料；
- 整理一下发到群里对齐。

同一堆事实，去向不同，写成的东西就该不同。给机构的不该是仓库说明；给开发者的不该是介绍文案。但无论去向是什么，**打开后都必须先是一份能看的腾讯文档**。

去向决定写什么。排版决定像不像文档。产品的本体是后者；前者是 AI 编排时必须做的判断。

---

## 3. 目标与非目标

### 目标

| ID | 目标 | 做到什么样 |
| :-- | :-- | :-- |
| G1 | 交出去能看 | 打开腾讯文档，是标题、段落、列表、表格各就其位的正文，不是草稿 |
| G2 | 敢直接发 | 用户愿意把链接发给他说的那种人，而不先改结构、删对话腔 |
| G3 | 按去向编排 | 同一件事，给机构与给开发者，取舍和语气明显不同 |
| G4 | AI 完成编排 | 用户交代去向即可，不必自己选模板、调格式、点标题层级 |
| G5 | 失败可见 | 排不像文档时，不把「创建成功」当成交付 |

### 非目标

- 做文档品种目录，品种外就不会写；
- 做企业品牌 Word / PPT 模板填空；
- 把对话或仓库无取舍地倒进腾讯文档；
- 让模型去选字体、字号、主题色、页边距；
- 自研腾讯文档编辑器，或用浏览器自动化点格式；
- 在腾讯文档能力未确认前，承诺流程图、白板、100% 复现人工精排。

## 4. 用户与场景

| 谁 | 他在干什么 |
| :-- | :-- |
| 正在做事的人 | 聊着聊着要交一份能发的文档，不想自己再排一遍 |
| 要对外的人 | 给机构、客户、合作方一个链接，打开就要像正式材料 |
| 要对齐的人 | 发群、发给开发者、发给同事，对方扫一眼就能读 |

主场景只有一类：**对话里生成，腾讯文档里打开，能发给别人。**

场景用去向区分，不用产品目录区分。下面是验收时用来检验「AI 有没有在编排」的例子，不是功能开关。

| 用户说 | AI 应当理解 | 打开后不该是 |
| :-- | :-- | :-- |
| 把项目做成介绍 | 这是什么、解决什么、现在怎样、从哪看 | 聊天记录，或文件清单 |
| 给第三方机构推 | 为何值得看、能提供什么、边界、下一步 | 内部黑话、目录结构 |
| 给开发者 | 如何开始、怎么接、约束和坑 | 市场文案，或没有结构的代码墙 |
| 整理后发群对齐 | 结论在前，该列表的列表，该表的表 | 对话全文 |

用户没说给谁时，问一句「给谁看、拿去做什么」。不问「请选择模板」。

## 5. 产品如何工作

用户侧应当像交代一件事，不像操作排版软件。

```text
对话里说出目的
    → AI 判断去向（给谁、拿去做什么）
    → AI 编排：写什么、不写什么、什么先被看见、哪里用列表/表格
    → 落成腾讯文档里能扫读的正文
    → 返回链接；打开即可看、即可发
```

### 5.1 去向

去向是编排的输入，不是模板名。用户说了就用；缺「给谁」时只问最关键的一句，不展开问卷。

### 5.2 智能编排

编排由 AI 完成，产品要求它每次都做到：

1. **主张：** 打开先看见这句话是干什么的；
2. **取舍：** 对这种读者有用的留下，内部拉锯、无关细节拿掉；不编造事实，缺的标成待确认；
3. **扫读结构：** 短段落、清楚的分节；对照做成表，步骤做成列表，不要一堵墙；
4. **像人写的文档：** 没有「好的我来写一份」、没有对话残片、没有未消化的 Markdown 符号。

同一项目三份文档如果标题不同、骨架却一样，编排就失败了。

### 5.3 排版

排版是把编排结果变成腾讯文档里正常人阅读的样子：

- 标题是标题，不是一行 `#`；
- 段落能换气；
- 列表是列表；
- 该对照的是表；
- 技术材料在腾讯文档做得到的范围内，才用代码或图。

排版发生在腾讯文档上。用户要的是那里打开好看，不是我们另做一套视觉皮肤，也不是套一份与读者无关的品牌 Word。

AI 负责编排判断；把判断落成文档结构，是产品必须保证的能力。不能把「模型把 Markdown 写整齐一点」当成排版已经完成。

### 5.4 交出去

返回链接、这份文档给谁、主张是什么。不要在聊天里再贴全文。默认新建文档。用户说「再来一版」是新文档或明确覆盖，不悄悄改别人已经评论过的链接。

## 6. 质量标准

唯一硬标准：

> 打开这条腾讯文档，你现在会不会把它直接发给你说的那种人？

会，才算交付。不会，就不是本产品。

出现任一情况即不合格：

- 像在继续聊天；
- 给机构的读起来仍是仓库说明，给开发者的读起来仍是介绍文案；
- 该分节的没分节，该用表的仍是长句；
- 标题看不出主张；
- 创建接口成功，打开仍是一坨。

试点可打 1–5 分，问的仍是上面那一句。目标平均不少于 4，并记下「不会」是因为去向错了、编排错了，还是腾讯文档里排不像文档。

## 7. 和现有插件的关系

| 已有 | 本产品补上 |
| :-- | :-- |
| 能创建、读取、改腾讯文档 | 创建出来的必须像文档 |
| 日程、会议、表格、待办等办公能力 | 不替代这些能力 |
| 办公机器人卡片上的允许修改开关 | 生成/写入仍受该开关约束 |

本产品是办公插件在「文档」上的质量层，不是新插件，也不是模板子系统。

## 8. 范围

### 现在就要成立的

- 对话里生成腾讯文档；
- AI 按去向编排；
- 打开能看、敢发；
- 用户不必选模板。

### 现在明确不做

- 模板中心、模板管理、客户上传品牌模板；
- 任意局部精修已有文档的格式（像在线编辑器那样改某一个字号）；
- 承诺所有图、白板、复杂版式；
- 公共云排版或把客户正文交给第三方渲染。

### 以后可以长出来、但不是先做的

会议纪要、评审规格、对外一页纸、新同事上手——只要去向清楚，编排就应当能写，不必先入库。开发者材料里的图、纪要行动项转待办，等腾讯文档侧能力清楚再加，不在本方案里假装已经有。

---

## 9. 私有化与安全（产品约束）

素材、正文、编排过程默认留在客户 DSH 环境；只经已授权的企业微信 / 腾讯文档通道交出去。不把客户材料交给公共排版或绘图服务当主路径。写操作遵循现有「允许修改」。缺的事实标待确认，不编造。
