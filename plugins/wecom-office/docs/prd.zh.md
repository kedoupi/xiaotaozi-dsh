## 1. 背景与问题

### 1.1 背景

企业微信官方已开源 [`wecom-cli`](https://github.com/WecomTeam/wecom-cli)，覆盖文档、日程、会议、待办、微盘、通讯录等办公能力，给 Agent 在终端调用。

小桃子现有 `dsh-im` 企业微信通道只做 **聊天**（`@wecom/aibot-node-sdk` 长连接：收消息、流式回复、文件）。用户在对话里问「今天下午有哪些会 / 帮我找周报」，模型摸不到企业微信里的数据。

### 1.2 要解决的问题

| ID | 问题 | 今天 | 目标 |
| :-- | :-- | :-- | :-- |
| P1 | 对话里用不了企微办公数据 | 只能聊天 | 开通后模型可查日程 / 文档 / 会议 / 联系人 |
| P2 | 官方 CLI 对用户太重 | 要自己 `auth init` | 设置里点一下；有 IM 则复用已绑机器人 |
| P3 | 本插件与 IM 独立安装 | 若只做「去 IM 绑定」则没装 IM 的人走不通 | 有 IM 借 IM 绑定；无 IM 本页自己绑 |

### 1.3 机会与约束

- **机会：** 身份与 IM 是同一对 Bot ID + Secret，不必让用户「再绑一个办公账号」。
- **约束：** CLI 与聊天 WebSocket 不是同一协议；本插件不实现收发消息。飞书官方是 MCP 不是 CLI，不在本期。用户可以只装本插件、不装 `dsh-im`。

## 2. 目标与非目标

### 2.1 产品目标

让用户在 **网页对话**（有 IM 时也包括企业微信里跟机器人说话）中，用自然语言使用企业微信的日程、文档、会议、通讯录，而不必学习 `wecom-cli`。

### 2.2 本期成功标准（可验收）

| ID | 标准 | 度量 |
| :-- | :-- | :-- |
| G1 | 有 IM 且已绑企微：设置里选 bot，点一次开通，不再扫码、不打开终端 | 走查 |
| G2 | 有 IM 未绑：主按钮引导用户打开侧栏 IM → 企业微信；绑完用户自己回到本页再点开通（第一刀不自动跳转/回跳） | 走查 |
| G3 | 无 IM：本页扫码或手动即可绑定并开通；无「请先安装 IM」、无假跳转 | 走查 |
| G4 | 开通后问「今天下午有什么安排」会调日历类工具（视企业是否开放 CLI 权限） | 真机 |
| G5 | 未开通 / 无 CLI 时工具失败原因可懂，不假装成功 | 走查 + 单测 |
| G6 | 第一刀无写工具；设置页不提供「允许修改」开关 | 走查 + 单测 |

### 2.3 非目标（本期不做）

| ID | 不做 | 原因 |
| :-- | :-- | :-- |
| OOS-1 | 企微长连接收消息、流式、模板卡片 | 仍在 `dsh-im`；CLI `message.send` / `chat.*` 已接到办公工具 |
| OOS-2 | 飞书日历 / 云文档 | 另开 `dsh-feishu-office`；官方是 MCP |
| OOS-3 | 包名 `dsh-im-office` | 与 IM 实验渠道 `office` 撞名 |
| OOS-4 | 把 `wecom-cli` 打进 Desktop / 插件 tarball | PATH 安装；不进桌面 runtime |
| OOS-5 | 无开关的默认写入 | 写操作受设置页「允许修改」约束，默认开 |
| OOS-6 | 有 IM 时在办公页再画扫码 | 绑定只走 IM |
| OOS-7 | 无 IM 时多 bot 账号库 | CLI 一份凭据；避免再造 IM |
| OOS-8 | 邮件全套 | 文档 / 表格 / 智能表格 / 智能文档已接入；邮件仍不做 |
| OOS-9 | 办公身份跟随「当前这条 IM 消息的 bot」 | 第一刀固定为设置里选中的一只 |

## 3. 用户与场景

### 3.1 用户

会在设置里点按钮的人。 **不** 假设会用终端，**不** 假设装了 `dsh-im`。

| 画像 | 典型状态 |
| :-- | :-- |
| 插件作者 / 沙箱 | Git path，`pnpm dev` :3081 |
| 已用 IM 绑过企微 | 主路径：一键开通 |
| 只用办公、不装 IM | 本页扫码 |
| 以后的 Desktop 用户 | 市场 / pack；本文不设计桌面捆绑 |

### 3.2 核心场景

| 场景 | 用户 | 关键路径 |
| :-- | :-- | :-- |
| S1 | 有 IM，已有 1～N 只企微 bot | 选一只 → 开通 → 对话里问日程 |
| S2 | 有 IM，还没有企微 bot | 引导打开 IM → 用户点企业微信绑好 → 自己回设置再开通 |
| S3 | 无 IM | 本页扫码或手动 → 绑定并开通 |
| S4 | 无 `wecom-cli` | 说明安装命令，按钮禁用 |
| S5 | 先开通再装 / 卸 IM | 已开通不丢；卸 IM 后不能再跳浮层 |
| S6 | 对话使用 | 「今天下午有哪些会」「找周报」「通讯录找张三」 |

## 4. 产品关系

```
用户说话
   ├─ 网页对话 ─────────────────────────────────┐
   └─ 企微里跟机器人说 ── dsh-im（可选）──► Harness 会话
                                                 │
                                                 ▼
                                       本插件 tools
                                                 │
                                                 ▼
                                            wecom-cli
                                                 │
                                                 ▼
                                       企微文档 / 日程 / 会议
```

| 面 | 插件 | 用户入口 |
| :-- | :-- | :-- |
| 聊天 | `dsh-im`（可选） | 侧栏 → IM机器人 → 企业微信 |
| 办公 | **本包** | 设置 → **企业微信办公**；对话里直接说 |
| 模型提醒 | 本包 systemPrompt | 用户不可见 |

同一只智能机器人，两套协议：IM = WebSocket 聊天；办公 = `wecom-cli`。身份都是 Bot ID + Secret。

## 5. 信息架构

### 5.1 入口

- **主入口：** 设置 → **企业微信办公**（`settings.section` id = `wecom-office`）。
- **不** 新增侧栏一级入口。
- **第二刀（可选）：** IM 企微机器人卡片「办公能力：未开通 →」。未装本插件则不显示。

### 5.2 设置页结构（一份页面，按模式换主按钮）

1. 标题：企业微信办公  
2. 一句说明（有 IM / 无 IM 文案不同，见 §8）  
3. 状态条（同一时间只一种主状态）  
4. 机器人选择（有则显示）  
5. 主按钮 + 次按钮  
6. 检查  
7. 高级（折叠）。第一刀 **不展示**「允许修改企业微信数据」

### 5.3 主状态

| 状态 | 含义 |
| :-- | :-- |
| 未安装 wecom-cli | PATH 无 CLI；绑定/开通禁用 |
| 尚未绑定企业微信机器人 | 无可用身份 |
| 未开通 | 有可选机器人，CLI 未授权当前身份 |
| 已绑定，开通失败 | 无 IM 扫码已拿到 bot，`auth init` 失败 |
| 开通失败 | 有 IM 路径下 `auth init` 失败 |
| 已开通 | `auth show` = authorized，且与当前办公身份一致 |

## 6. 模式：有没有 IM

打开设置页先判定 **当前 profile 是否加载了 IM**（插件在跑，不是磁盘有没有旧文件）。

| 信号 | 有 IM | 无 IM |
| :-- | :-- | :-- |
| 侧栏能打开 IM 浮层 | 是 | 否 |
| Host 能看到 `dsh-im` 层 | 是 | 否 |
| 仅残留 `integrations/dsh-wecom/` | **否** | 是 |

Host 快照下发 `imAvailable`（Client `imAvailableHint` **或** 已加载的 `im` 插件；磁盘残留不算）。Client **只信** 该字段。卸了 IM 还跳浮层 = 缺陷。

| 模式 | 绑定发生在 | 办公页做什么 |
| :-- | :-- | :-- |
| 有 IM | **只在 IM** | 选 bot、开通、去绑定（跳转） |
| 无 IM | **本页** 扫码 / 手动 | 绑定并开通；禁止「请先安装 IM」 |

## 7. 用户流程

### 7.1 S1 有 IM + 已绑（主路径）

1. 打开设置 → 企业微信办公。  
2. 下拉列出 IM 企微 bots（显示名 + 打码 Bot ID）。规则 §9。  
3. 选中一只 → **开通办公能力**。  
4. 已开通。对话里问日程/文档。

用户不必知道 CLI / `auth init` / 凭据文件。

### 7.2 S2 有 IM + 未绑

**去**

1. 状态：尚未绑定企业微信机器人。  
2. 主按钮 **去绑定企业微信**。办公页 **不** 画二维码。  
3. 第一刀 **不改 dsh-im、不程序化选中企业微信 tab**（IM 默认打开在微信渠道）。按钮点击侧栏 `[data-im-hub-entry]`（若存在），并写明：「在浮层左侧点 **企业微信**，用扫码或手动接入。完成后回到本页点检查，再开通。」  
4. 用户绑完后自己打开设置 → 企业微信办公。下拉出现新 bot。**禁止自动开通**。

逃生门（浮层没有或点不了）：本页 **手动接入** Bot ID + Secret（有 IM 时非主路径）。

第二刀（不在第一刀验收）：`openImHub({ channel: 'wecom' })`、关设置、绑完顶条回跳。

### 7.3 S3 无 IM

独立主路径，不是高级里两行。

说明：「也可以先装 IM 机器人，在聊天里绑好再回来开通。现在没有 IM，就在本页扫码或填凭据。」  
禁止主按钮「请先安装 IM」。

| 操作 | 行为 |
| :-- | :-- |
| 扫码绑定（优先） | 官方企微建机器人二维码。成功后 **自动开通**。成功 → 已开通；开通失败 → 「已绑定，开通失败」+ **重试开通**（不必再扫）。无聊天通道，绑定与开通可连做。 |
| 手动接入 | Bot ID + Secret → **绑定并开通**。Secret 不进设置 JSON。同一 Bot ID 再绑 = 覆盖本页这一只。 |

无 IM 第一刀 **只一只** 办公机器人。以后装 IM 见 7.5。

### 7.4 S4 无 CLI

状态：未安装 wecom-cli。展示 `npm install -g @wecom/cli`。绑定与开通禁用。「检查」可再探 PATH。

### 7.5 S5 装上 / 卸掉 IM

| 变化 | 办公页 |
| :-- | :-- |
| 无 IM 已开通 → 装上 IM | 保持已开通。下拉 = IM 列表 ∪ 当前身份（IM 没有则标「仅办公，未用于聊天」）。不自动改办公身份。 |
| 有 IM 已开通 → 卸掉整个 IM | 凭据仍在则 **保持已开通**。只展示当前一只，标「IM 已卸，仅办公」。主按钮不再「去绑定」。换号走 7.3。 |
| 有 IM，卸的是当前办公那只 bot，IM 还在 | 办公未开通，清该身份凭据，**不**自动改绑剩下的 bot（§9）。 |
| 无 IM，用户清除办公身份 | 回到 7.3。 |

### 7.6 S6 开通之后怎么用

无新入口。与「记忆」一样：说话。

| 用户说 | 期望 |
| :-- | :-- |
| 今天下午有哪些会 | 查日程；必要时再查会议（查询不追问） |
| 帮我找周报 | 搜文档 |
| 张三在吗 | 搜联系人 |
| 帮我约明天下午三点的会 | 第一刀：不能创建 / 提示未开写入 |

有 IM 时，在企微里对机器人说同样的话也成立（消息进 Harness，工具已挂上）。

## 8. 界面规格

### 8.1 文案原则

- 用户可见中文；`wecom-cli`、Bot ID、PATH 保留英文。  
- 禁止对用户出现：discovery、schema、Bearer、`auth init`（作者/高级兜底除外）。  
- 失败说人话，例如：「这只机器人没有办公权限，请在企业微信里确认智能机器人已开通 CLI 能力。」再映射 CLI errmsg。

### 8.2 说明句

- 有 IM：开通后可在对话里查日程、文档和会议。聊天仍在「IM机器人」。  
- 无 IM：开通后可在对话里查日程、文档和会议。若要在企业微信里跟机器人说话，再装 IM 机器人。

### 8.3 机器人选择

- 有 IM 且列表非空：单选下拉，见 §9。  
- 无 IM 且已有办公身份：只读展示这一只。  
- 无机器人：不展示下拉。

### 8.4 主按钮矩阵

| 条件 | 主按钮 |
| :-- | :-- |
| 无 CLI | 禁用 |
| 有 IM、无 bot | 去绑定企业微信 |
| 有 IM、有 bot、选中 = 当前办公身份 | 开通办公能力 / 重新开通 |
| 有 IM、有 bot、选中 ≠ 当前办公身份 | **开通这只机器人** |
| 无 IM、无 bot | **扫码绑定**（旁：手动接入） |
| 无 IM、已绑定未开通或开通失败 | **重试开通** |

### 8.5 高级

- 折叠：CLI 路径、`configDir` 只读。  
- 有 IM：手动 Secret **不**作为主入口（主手动在 IM）。  
- 无 IM：手动接入在首屏，不藏死在高级里。

### 8.6 允许修改

第一刀 **不展示该开关、不交付写工具**（Q1 已定）。第二刀再加开关，默认关。

## 9. 账号与多 Bot

### 9.1 原则

同一只机器人，两套协议，一份用户心智。

- 有 IM：不要说「再绑一个办公账号」。  
- 无 IM：不要逼用户先装 IM。

办公身份 **同一时间只有一只**。IM 可多 bot 收消息；「我的日程」必须落在一个 Bot ID。

### 9.2 有 IM 时下拉

每项：显示名 + 打码 Bot ID；当前办公身份标记「当前办公」。第一刀 **不展示** WebSocket 在线/离线。  
页上固定句：「对话里查日程和文档时，用下面选中的这只机器人。」

**尚无办公身份时的默认选中（不静默开通）：**

1. 刚从 7.2 回来 → 刚绑的那只  
2. 否则列表第一只（IM `config.json` 数组顺序）  
3. 用户可改下拉。开通不依赖 IM 是否连着 WebSocket。

**已开通后：**

- 钉死当前身份。新绑的 bot **不抢**。  
- 换号：改下拉 → 按钮变为「开通这只机器人」→ 再点才覆盖。离开未点 = 仍用旧身份。  
- 成功后确认：「已改为用「某某」查日程和文档。」

**卸掉当前办公那只（IM 还在）：**

- 办公未开通，清 CLI 凭据。  
- 还有别的 bot：按上面默认规则预选，**不**自动开通。  
- 一只不剩：回到 7.2。

### 9.3 对话用哪只

网页对话与企微来的消息：**一律**用设置里的办公身份，不跟随「当前消息是哪个 IM bot 送来的」。

### 9.4 用户不必做的

- 开通时再扫一次给 CLI  
- Secret 填两处  
- 配置 `~/.config/wecom`  
- 没装 IM 还去侧栏找 IM 机器人  

凭据目录：`$DSH_HOME/plugins/wecom-office`（沙箱 / 正式隔离）。

## 10. 模型侧（用户间接感知）

开通且只读时，相关问题应调工具，不要猜。

- 查企微日程 / 文档 / 会议 / 联系人 → 本插件工具。  
- 创建「会」：第一刀直接说还不能创建。第二刀才消歧「需要创建日程还是会议？」（问题原文固定）。  
- 查询「最近有什么会」：不追问；先日程，必要时会议。  
- 不管发微信消息。

## 13. 风险

| ID | 风险 | 用户感受 | 缓解 |
| :-- | :-- | :-- | :-- |
| R1 | 企业未开放 CLI | 开通失败 | 文案归企微权限，非小桃子损坏 |
| R2 | 日程与带会议号的会混淆 | 查错/改错 | 第一刀只读；创建留第二刀消歧 |
| R3 | 只装办公未开通 | 模型说没有日历 | 状态页一眼能懂 |
| R4 | 多 bot 用错身份 | 查到别人的日历 | 页上标明当前办公身份；不跟消息来源 bot |
| R5 | 无 IM 扫码与 IM 扫码两套 UI 漂移 | 体验不一致 | QR 协议对齐 IM；产品说明同一官方页 |
| R6 | 回跳依赖改 IM | 绑完找不到办公页 | P1 降级文案；发布说明写明 |
