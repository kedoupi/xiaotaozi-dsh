## 1. 背景与问题

### 1.1 背景

企业微信官方已开源 [`wecom-cli`](https://github.com/WecomTeam/wecom-cli)，覆盖文档、日程、会议、待办、微盘、通讯录等办公能力，给 Agent 在终端调用。

小桃子的 `dsh-im` 企业微信通道做 **聊天**（`@wecom/aibot-node-sdk` 长连接：收消息、流式回复、文件），`dsh-wecom-office` 把 `wecom-cli` 接到模型工具上做 **办公**。用户在对话里问「今天下午有哪些会 / 帮我找周报」，办公工具负责落地。

### 1.2 要解决的问题

| ID | 问题 | 旧版 | 目标 |
| :-- | :-- | :-- | :-- |
| P1 | 对话里用不了企微办公数据 | 只能聊天 | 开通后模型可查日程 / 文档 / 会议 / 联系人 |
| P2 | 官方 CLI 对用户太重 | 要自己 `auth init` | 机器人卡片上点一下开通，复用已绑机器人 |
| P3 | 用户要理解两个插件 | 先在 IM 绑 bot，再去独立办公设置页选同一只 bot | 用户只在 IM 机器人卡片操作，不知道有第二个包 |

### 1.3 机会与约束

- **机会：** 身份与 IM 是同一对 Bot ID + Secret，卡片就是用户已有的那只机器人。
- **约束：** CLI 与聊天 WebSocket 不是同一协议；本插件不实现收发消息。飞书官方是 MCP 不是 CLI，不在本期。

## 2. 目标与非目标

### 2.1 产品目标

用户在 **网页对话**（也包括企业微信里跟机器人说话）中，用自然语言使用企业微信的日程、文档、会议、通讯录，而不必学习 `wecom-cli`，也不必离开 IM 机器人管理界面。

### 2.2 本期成功标准（可验收）

| ID | 标准 | 度量 |
| :-- | :-- | :-- |
| G1 | 已绑企微 bot：在对应卡片点一次开通，不扫码、不开终端、不进设置页 | 走查 |
| G2 | 多 bot：在目标卡片显式「设为办公机器人」，同一时间只有一只办公身份 | 走查 + 单测 |
| G3 | 开通后问「今天下午有什么安排」会调日历类工具（视企业是否开放 CLI 权限） | 真机 |
| G4 | 未开通 / 无 CLI / office host 不可用时卡片状态和工具错误可懂，IM 聊天不受影响 | 走查 + 单测 |
| G5 | 当前办公机器人卡片可管理「允许修改企业微信数据」，关闭后写工具 fail closed | 走查 + 单测 |
| G6 | 已有办公凭据和配置升级后继续在对应卡片显示已开通，不要求重新授权 | 兼容测试 |

### 2.3 非目标（本期不做）

| ID | 不做 | 原因 |
| :-- | :-- | :-- |
| OOS-1 | 企微长连接收消息、流式、模板卡片 | 仍在 `dsh-im`；CLI `message.send` / `chat.*` 已接到办公工具 |
| OOS-2 | 飞书日历 / 云文档 | 官方是 MCP；真实需求出现后另行设计 |
| OOS-3 | 把 `wecom-cli` 打进插件 tarball | PATH 安装 |
| OOS-4 | 无开关的默认写入 | 写操作受「允许修改」约束，默认关 |
| OOS-5 | 办公身份跟随「当前这条 IM 消息的 bot」 | 办公身份固定为卡片上显式选中的一只 |
| OOS-6 | 独立办公设置页 / 办公页扫码 / 办公页手动绑定 | 单入口：绑定只在 IM，办公操作只在机器人卡片 |
| OOS-7 | 通用 integrations shell / 合并两个包 | 不提前抽象；两包保持独立 |
| OOS-8 | 邮件全套 | 文档 / 表格 / 智能表格 / 智能文档已接入；邮件仍不做 |

## 3. 用户与场景

### 3.1 用户

会在机器人卡片上点按钮的人。**不**假设会用终端。默认 `xtz` 同时装 `dsh-im` 和 `dsh-wecom-office`。

### 3.2 核心场景

| 场景 | 用户 | 关键路径 |
| :-- | :-- | :-- |
| S1 | 已有 1～N 只企微 bot | 目标卡片 → 开通办公能力 → 对话里问日程 |
| S2 | 还没有企微 bot | 先在 IM 企业微信渠道绑 bot（扫码或手动），回到卡片再开通 |
| S3 | 无 `wecom-cli` | 卡片展示安装命令，开通禁用，可重新检查 |
| S4 | 多 bot 换办公身份 | 目标卡片「设为办公机器人」；失败保留原身份并回滚 CLI |
| S5 | 删掉当前办公 bot | 办公激活清除、CLI 凭据清除，剩余 bot 不自动接管 |
| S6 | 对话使用 | 「今天下午有哪些会」「找周报」「通讯录找张三」 |

## 4. 产品关系

```
用户说话
   ├─ 网页对话 ─────────────────────────────────┐
   └─ 企微里跟机器人说 ── dsh-im ──► Harness 会话
                                                 │
                                                 ▼
                                    dsh-wecom-office tools
                                                 │
                                                 ▼
                                            wecom-cli
                                                 │
                                                 ▼
                                       企微文档 / 日程 / 会议
```

| 面 | 插件 | 用户入口 |
| :-- | :-- | :-- |
| 聊天 | `dsh-im` | 侧栏 → IM机器人 → 企业微信 |
| 办公（UI） | `dsh-im` 机器人卡片「办公能力」区 | 同上一张卡片 |
| 办公（host / 工具） | `dsh-wecom-office`（无独立 UI） | 用户不可见；对话里直接说 |
| 模型提醒 | `dsh-wecom-office` systemPrompt | 用户不可见 |

同一只智能机器人，两套协议：IM = WebSocket 聊天；办公 = `wecom-cli`。身份都是 Bot ID + Secret。

**内部两个包，用户一个入口。** 只装 `dsh-wecom-office`、没装 `dsh-im` 时没有任何办公 UI；官方 `xtz` 默认同时种两包。

## 5. 信息架构

### 5.1 入口

```text
主入口：IM 机器人 → 企业微信 → 对应机器人卡片
无独立「企业微信办公」设置入口
只装 dsh-wecom-office 时无 UI
```

### 5.2 卡片「办公能力」区

每张企业微信机器人卡片一个办公区块，同一时间只一种主状态：

| 状态 | 卡片显示 | 主操作 |
| :-- | :-- | :-- |
| CLI 未安装 | 未安装 `wecom-cli` | 展示 `npm install -g @wecom/cli`；重新检查 |
| 未开通 | 办公能力未开通 | 开通办公能力 |
| 当前办公机器人 | 办公能力已开通 | 展开办公设置 / 重新检查 |
| 其他机器人 | 不是当前办公机器人 | 设为办公机器人 |
| 开通失败 | 可理解的错误 | 重试 |
| Office host 不可用 | 办公能力暂不可用 | 重新检查（IM 聊天不受影响） |

### 5.3 当前办公机器人卡片的展开区

- 「允许修改企业微信数据」开关（默认关，关闭时写工具 fail closed）。
- CLI 安装 / 授权状态。
- CLI 路径、`configDir` 等高级只读信息。

## 6. 用户流程

### 6.1 S1 开通（主路径）

1. 打开侧栏 IM机器人 → 企业微信。
2. 目标机器人卡片「办公能力」区点 **开通办公能力**。
3. 卡片显示已开通。对话里问日程 / 文档。

用户不必知道 CLI / `auth init` / 凭据文件，也不离开 IM 界面。

### 6.2 S2 未绑 bot

卡片办公区不影响绑定流程。用户在企业微信渠道用原有扫码 / 手动方式绑 bot，绑完卡片出现办公区。**不自动开通。**

### 6.3 S4 显式切换

1. 在另一只 bot 的卡片点 **设为办公机器人**。
2. host 先保存原身份，对新 bot 做 CLI 鉴权。
3. 成功：写入新办公身份，全部卡片刷新。
4. 失败：用原身份凭据回滚 CLI，原办公机器人继续可用；错误显示在用户操作的目标卡片上。回滚也失败时明确报告办公鉴权不可用，不假装原身份正常。

**不**根据消息来自哪只 bot 自动切换办公身份；只能显式点卡片。

### 6.4 S5 删除当前办公 bot

办公插件在下一次 `status` 时发现办公身份已不在 IM 列表：清除激活状态和 CLI 凭据。剩余机器人只在卡片上预备显示，不自动接管。

### 6.5 S6 开通之后怎么用

无新入口。开通后在对话里直接说。有 IM 时，在企微里对机器人说同样的话也成立（消息进 Harness，工具已挂上）。

## 7. 界面规格

### 7.1 文案原则

- 用户可见中文；`wecom-cli`、Bot ID、PATH 保留英文。
- 禁止对用户出现：discovery、schema、Bearer、`auth init`、secretRef。
- 失败说人话，例如：「这只机器人没有办公权限，请在企业微信里确认智能机器人已开通 CLI 能力。」再映射 CLI errmsg。
- 界面永远不展示 Secret、secretRef 或完整远程 Bot ID（只展示打码形式）。

### 7.2 说明句

卡片办公区说明：开通后可在对话里查日程、文档和会议。聊天绑定仍在本页完成。

---

## 8. 账号与多 Bot

### 8.1 原则

同一只机器人，两套协议，一份用户心智。

办公身份 **同一时间只有一只**。IM 可多 bot 收消息；「我的日程」必须落在一个 Bot ID。

### 8.2 卡片选择是显式的

- 开通 / 切换只发生在用户点击目标卡片按钮时。
- 新绑的 bot 不抢办公身份；删掉的不是办公 bot 时办公身份不变。
- 系统 **不** 跟随「当前这条 IM 消息来自哪只 bot」切换办公身份；网页对话与企微消息一律用当前办公身份。

### 8.3 用户不必做的

- 开通时再扫一次给 CLI
- Secret 填两处
- 配置 `~/.config/wecom`
- 找一个单独的办公设置页

凭据目录：`$DSH_HOME/plugins/wecom-office`（沙箱 / 正式隔离）。

## 9. 模型侧（用户间接感知）

开通且只读时，相关问题应调工具，不要猜。

- 查企微日程 / 文档 / 会议 / 联系人 → 办公工具。
- 写操作受「允许修改」约束；关闭时写工具直接失败并说明，不假装成功。
- 查询「最近有什么会」：不追问；先日程，必要时会议。
- 不管发微信消息（聊天是 IM 的事）。

## 12. 风险

| ID | 风险 | 用户感受 | 缓解 |
